# Controlling Excel Variance Analysis

A tested Excel controlling workbook: budget-vs-actual variance analysis, a monthly trend view, a year-over-year comparison, and an ad-hoc exception report. It covers standard and ad-hoc controlling reports in Excel and supports annual budget planning with variance analysis.

## What it does

- `src/generate_data.py` generates a synthetic 24-month (2025–2026) controlling dataset for a mid-size company shaped like a bakery/retail business: 9 cost centers (production, retail stores, logistics, purchasing, admin, marketing) × 7 cost accounts (Personalkosten, Materialaufwand, Energiekosten, etc.) = 1,512 rows, each with a budget figure and an actual figure. The generator injects deliberate signal, not just random noise: a sustained fuel-cost overrun in Logistik starting April 2026, a one-off equipment-repair spike in Produktion Backwaren in March 2026, and a consistent ~12% underspend in Marketing, so the variance analysis has something real to find.
- `src/build_workbook.py` builds `controlling_report_2025_2026.xlsx` with five sheets: **Rohdaten** (raw fact table), **Kostenstellen-Uebersicht** (budget vs. actual by cost center, with conditional formatting flagging >10% deviations), **Monatsverlauf** (budget vs. actual by month), **YoY-Vergleich** (2025 vs. 2026 by cost center), and **Abweichungs-Report** (every cost-center/account/month combination where the deviation exceeds both 15% and €500, sorted by absolute deviation, an ad-hoc exception report a controller can use directly).

## Data

All data is synthetic, generated by a seeded PRNG. The workbook is a standalone Excel deliverable with no SQL Server / OLAP source system behind it (the separate `sql-olap-controlling-reporting` project covers the SQL Server/OLAP side), so real data can be dropped into the `Rohdaten` sheet's structure. The project covers the reporting and variance-analysis side of controlling; budget-setting workflows such as target negotiation and approval are not modeled.

## Design: formulas instead of a native PivotTable

Excel's pivot table is normally built by pointing Excel at a data range and letting Excel construct the pivot cache and layout. openpyxl can write a `PivotCacheDefinition`/`PivotTable` XML structure programmatically, but producing one that Excel opens cleanly and refreshes correctly from a non-Excel-authored write is unreliable in practice.

Instead, every summary sheet is built with live `SUMIFS` and `SUMPRODUCT` formulas against the raw data range, the same day-to-day ad-hoc analysis a controller does directly in Excel, and fully verifiable by tests. This is the same approach as `powerquery-sap-reporting`: a different tool, chosen because it can be verified end-to-end here, and not strictly identical to what a native pivot table would produce.

## Tests

The test suite (`tests/test_workbook.py`, 10/10 passing) goes beyond checking that openpyxl wrote plausible-looking formula strings. It:

1. Regenerates the source data independently.
2. Builds the workbook.
3. Forces LibreOffice Calc, a real, independent spreadsheet engine, to open the file headless and recalculate every formula, then re-saves it.
4. Reads back the recalculated values (not the formula strings) and cross-checks every cost-center total, monthly total, and YoY figure against an independent pandas `groupby().sum()` computation of the same raw data.

This catches a formula that parses but computes the wrong aggregation, or one that LibreOffice/Excel can't evaluate at all.

Tests also confirm that the injected Marketing underspend shows up as a genuine >8% negative deviation (not noise), that the one-off equipment-repair spike is flagged in the exception report, and that the exception report is correctly sorted and threshold-filtered.

## Project structure

```
src/
  generate_data.py                    -- seeded synthetic controlling dataset
  build_workbook.py                   -- formula-driven workbook builder
  controlling_report_2025_2026.xlsx   -- generated workbook
tests/
  test_workbook.py                    -- 10 tests, including LibreOffice recalculation
```

## Running it

```bash
cd src && python3 build_workbook.py
cd .. && python3 -m pytest tests/ -v
```
